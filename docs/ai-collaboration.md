# AI Collaboration in App Projects — Mailbox Convention

- **Status:** accepted 0.1 (2026-08-05, approved by Jörg)
- **Applies to:** every app project with a shared git repository and at
  least one AI coding agent; complements the App Deployment Contract
  (becomes part of it once accepted) and every project briefing.

## 1. Why

App projects involve several AI agents that never share a session: the
app-side coding agent (e.g. the pilot CRM's Codex) and the
platform-side agent (Claude), plus the humans around them. The humans
will not reliably relay messages — the platform operator sees test
results the app developer's agent needs, and neither human should have
to copy-paste between AIs. The **shared project repository is the one
channel both sides already have**, so it carries the correspondence:
an "AI mailbox" of letters and reports, readable by every human in the
loop.

## 2. Repository layout

The project repository gets a top-level `collab/` directory:

```text
collab/
  letters/   one file per letter, never edited after sending
  reports/   test results, review findings, deployment feedback
```

**Letter files** are Markdown, named
`YYYY-MM-DD-<from>-<slug>.md` (date, sender, short topic), with a
small header:

```markdown
---
from: oaap-platform (Claude)
to: kutzke-karries-crm (Codex)
date: 2026-08-04
subject: Findings from deploying 0.2.0 to the test channel
re: 2026-08-03-crm-codex-questions.md   # only when answering
---

Letter text …
```

**Reports** are free-form Markdown or data files (e.g. a test log),
named with the same date-first pattern. A report is announced by a
letter when it needs action; routine reports may stand alone.

## 3. Rules for agents

These rules go verbatim (or translated) into every project briefing:

1. **Pull first.** At the start of every working session: `git pull`,
   then read new letters addressed to you or to `all`. Your human will
   not remind you — checking the mailbox is your job.
2. **Letters are immutable.** Never edit or delete a file another
   agent wrote. To respond, write a new letter with the `re:` header.
3. **Send immediately.** Commit and push a letter as soon as it is
   written — an unpushed letter does not exist.
4. **Write letters for:** questions to the other side, handover notes,
   review feedback, test results that need action, and announcements
   (e.g. "0.2.0 is deployed on the test channel, please verify the
   fix for X"). Keep this correspondence out of commit messages.
5. **Humans read along.** Letters are written so the humans in the
   project can follow them — in this program's projects: German,
   plain language, no session-internal shorthand.

## 4. Interplay with remote deployment

With the deploy hook (`oaap.apps.runtime` §2.5) the loop closes
without any human relay: the app agent pushes, triggers the deploy,
tests the result, and finds the platform side's feedback as letters in
the same repository — and answers there.

## 5. Outlook

If the convention proves itself in the pilot, it becomes the standard
collaboration channel generated by the Studio for every new project
(the `collab/` directory is part of the repository template).

## German summary / Deutsche Zusammenfassung

Projekt-KIs (App-Seite, z. B. Bernds Codex, und Plattform-Seite,
Claude) teilen keine Session — aber sie teilen das Projekt-Repo. Also
läuft die Korrespondenz dort: der **KI-Postkasten** im Verzeichnis
`collab/` mit `letters/` (Briefe, eine Datei pro Brief:
`JJJJ-MM-TT-<absender>-<thema>.md` mit kleinem Kopf aus from/to/date/
subject/re) und `reports/` (Testergebnisse, Review-Befunde). Die fünf
Regeln für jedes Briefing: (1) **Erst pullen** und neue Briefe lesen —
zu Beginn jeder Session, unaufgefordert. (2) **Briefe sind
unveränderlich** — antworten heißt: neuer Brief mit `re:`-Kopf.
(3) **Sofort senden** — ein ungepushter Brief existiert nicht.
(4) Briefe für Fragen, Übergaben, Review-Feedback, Testergebnisse und
Ankündigungen — nicht in Commit-Messages verstecken. (5) **Menschen
lesen mit** — Deutsch, klare Sprache, kein Sitzungs-Jargon. Zusammen
mit dem Deploy-Hook (Runtime-Spec §2.5) schließt sich der Kreis ohne
menschliches Weiterreichen: pushen, ausrollen, testen, Feedback als
Brief im selben Repo. Bewährt sich das im Pilot, wird `collab/`
Standard-Bestandteil jedes Studio-Projekt-Repos.
